The World Bank Knowledge Graph

A library of World Bank publications that sorts itself into a domain graph as documents arrive, and an agent that answers questions with page-level citations it checks.

liteparseJev · TypeSafe System One GLM 5.3 flash · Workers AICloudflare VectorizeSQLite FTS5
October 2026
Why

Thousands of reports, a fixed taxonomy, and keyword search

New documents don't fit

Hand-maintained topic lists lag behind what the Bank publishes. Each new theme needs someone to notice it and add a category.

Search misses meaning

Keyword search finds "debt" but not "fiscal space". Semantic search finds meaning but ranks loosely. Neither one says which page the answer is on.

Chatbots invent things

A generic LLM answers fluently, but nothing ties each sentence to a source, and nothing checks the source actually says it.

Goal

Every document is parsed, placed in a domain graph that grows by itself, and indexed two ways. Users see sources as they type, and every answer cites document and page, with each citation checked.

Ingestion

Five steps per document, resumable at each one

01

Acquire

Query the Documents API across 24 themes, round-robin. Skip files over 25 MB and anything without a %PDF- header.

146 PDFs
02

Parse

liteparse returns text per page. Strip disclosure stamps, cap at 80 pages, reject scans with no text layer.

~1 s / 45 pages
03

Chunk

About 1,100 characters, cut at sentences, never across pages, so every chunk keeps its page number for citations.

18k chunks
04

Route

Jev scores the document against the whole tree. Below threshold, GLM creates domains. Runs one document at a time.

Jev ≈ 0.2 s GLM ≈ 15–55 s
05

Index

Embed title + chunk, upsert NDJSON to Vectorize in batches of 500. Up to four documents in flight behind routing.

≈3 s / doc

Why routing is sequential

Each document may add a domain. The next document has to be scored against the tree that includes it, or two near-identical domains get created in parallel.

Status column = checkpoint

downloaded → parsed → routed → indexed. A crash or transient API error resumes from the last finished step; nothing is redone.

Knowledge Graph4
The domain graph

Jev decides if a document fits. GLM writes a new domain only when it doesn't.

One Jev call per document

  • State: title, country, type, abstract, a short excerpt. Kept small, since Jev loses accuracy with irrelevant text.
  • Questions: a noul (yes/no probability) per area and per domain, with structured instructions: {domain:{name, description, part_of}, question}.
  • Accept every domain ≥ 0.7 whose area ≥ 0.35, up to 4 tags. Nouls rather than one Choice, because a report can belong to several domains.
  • Otherwise GLM gets the tree, the three nearest misses with their scores, and the document, and returns 1–2 domains as JSON, placed under an existing or new area.

Knowledge Graph6
Retrieval

Two rankings fused, then graded by Jev

BM25

Keyword

SQLite FTS5 with the Porter stemmer. Prefix-matches the last word, so partial words work while typing.

VECTOR

Semantic

bge embedding of the query, top 50 from Vectorize. Ids map straight back to local chunks.

RRF k=60

Fusion

Reciprocal rank fusion, an optional domain scope, and at most 3 chunks per document so one long report can't fill the list.

JEV

Grade

One call, a noul per passage: "does it help answer the question?" Keep ≥ 0.35, up to 8. In testing, 8 of 14 passages survived.

Why both rankings

BM25 catches exact terms (country names, program acronyms, "IDA20") that embeddings blur. Vectors catch paraphrase ("fiscal space" ≈ "debt headroom"). BM25 is also instant, and it covers the few seconds before a newly upserted vector becomes queryable in Vectorize.

Design rule

Jev decides. GLM writes. Code does the rest.

TaskWhoWhy
Does this document belong to domain X?JevBounded yes/no, needs a calibrated probability to threshold, runs for every document
Which domains is this question about?JevRuns while the user types, so it has to come back in about 100 ms
Is this passage useful? Is this claim supported?JevMany independent checks, all answered in parallel in a single call
Which line is the document's title?JevCode proposes line spans from page 1; Jev picks one, so it can't invent a title
Name and describe a new domainGLMNeeds new text. Jev can only choose among options it is given

Known limits and next steps

What to fix next

Answer latency

GLM 5.3 flash always reasons before it writes, and that can't be turned off. A trivial reply takes ~16 s. Options: a non-reasoning model for the final write-up, or streaming a Jev-ranked extractive summary first.

Thin domains

At threshold 0.7 with 146 documents, many domains hold one or two reports. Lowering to ~0.6, or a periodic merge pass (Jev scoring domain pairs), would consolidate them.

Coverage

OCR is off and only the first 80 pages of each document are parsed. Scanned annexes and the back half of long reports aren't searchable yet.

Operations

No authentication on the public endpoint, so every question costs Jev and Cloudflare credits. The server should run as a service with restart-on-failure, and access should be restricted.
